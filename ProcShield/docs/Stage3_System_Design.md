# Stage 3 – System Design and Architecture

## System Design

ProcShield is designed around a Supervisor that controls and monitors a
separate TestService process.

The design separates process management, monitoring, resource checking and
event reporting into different components.

## Overall Architecture

The Supervisor acts as the central component of the system and coordinates
the TestService with the monitoring and recovery components.

ServiceManager handles the service lifecycle, while ProcessMonitor,
ResourceMonitor and EventLogger handle their respective responsibilities.

## Component Responsibilities

### Supervisor

Supervisor coordinates the complete monitoring and recovery process.

It receives information from the monitoring components and decides what
action should be taken when a failure is detected.

### ServiceManager

ServiceManager manages the lifecycle of TestService.

It is responsible for starting the service and stopping it when recovery or
shutdown requires the process to be terminated.

### ProcessMonitor

ProcessMonitor observes the TestService process and its heartbeat activity.

It provides information about process termination and helps identify when
the service has stopped responding.

### ResourceMonitor

ResourceMonitor checks the memory usage of TestService through the Linux
`/proc` filesystem.

The observed memory value is compared with the configured limit to identify
resource-limit violations.

### EventLogger

EventLogger handles important events generated by ProcShield.

It provides event output through application logging, the character device
and UDP communication.

### TestService

TestService is the child process monitored by ProcShield.

It sends periodic heartbeat information through a pipe so that the
Supervisor can determine whether the service is responding.

### Character Driver

The Linux character driver provides the `/dev/procshield` interface.

It allows the user-space monitoring application to send service events to
the kernel through standard character-device operations.

## Component Interaction

The Supervisor connects the different components and acts as the main
coordination point.

Monitoring information is received from ProcessMonitor and ResourceMonitor,
while ServiceManager performs the required service lifecycle operations.

## Process Lifecycle Design

The Supervisor starts TestService as a child process and maintains its
process information while it is running.

Process termination is observed using Linux process-management mechanisms,
allowing normal and abnormal termination to be handled differently.

## Monitoring Design

ProcShield uses three main monitoring mechanisms: process status,
heartbeat activity and memory usage.

These checks allow the system to identify crashes, unresponsive service
conditions and memory-limit violations.

## Failure Detection

A crash is detected when TestService terminates unexpectedly or because of a
signal.

A hang is detected when the expected heartbeat is not received within the
configured timeout, while memory usage is checked against its limit.

## Recovery Design

When a recoverable failure is detected, ProcShield records the event and
stops the affected service when required.

The Supervisor then checks the restart limit, applies the restart delay and
starts TestService again when recovery is allowed.

## Event Communication

Important service events are passed to EventLogger for reporting.

Events can be written to `/dev/procshield` and sent through UDP to the local
receiver using port `8080`.

## Kernel and User-Space Interaction

The main ProcShield application runs in user space, while the character
device operates in kernel space.

Communication between them takes place through the `/dev/procshield` device
file using standard `open`, `read` and `write` operations.

## Data and State Handling

The system maintains information such as the TestService process ID,
heartbeat timing, memory usage and restart count.

These values are used by the Supervisor to determine the current service
condition and select the appropriate recovery action.
